# V042: Test reads an env:// variable that only POSIX sets

## Overview

Dogfooding rule that checks reveal's own `tests/` for string literals naming an `env://`
URI for a variable Windows runners do not have: `HOME`, `USER`, `SHELL`, `TERM`, `LOGNAME`.
A test that reads one fails on the Windows legs only (BACK-1554, BACK-1556), and a test that
never checks the URI succeeded passes there while its assertions check nothing.

It is the tree scan of `tests/test_portable_env_vars.py` moved into `reveal reveal:// --check`
(BACK-1707): same literal matcher, same files, same findings (none on the current tree).

Only fires via `reveal reveal:// --check` (self-check of the dev checkout); it
does not run against user code.

## Rule Details

- **Code**: V042
- **Category**: validation
- **Severity**: MEDIUM
- **File Patterns**: `reveal://` self-check only (`internal = True`)

Scans `test_*.py` and `conftest.py` under `tests/`, except `tests/fixtures/` (sample sources).
Flags a non-docstring string literal containing `env://<VAR>` for one of the five names.

Not flagged: docstrings; a rendered value such as `env://HOME:/home/user` (the name is
followed by `:`, so it reads no environment); another variable sharing a prefix
(`env://HOMEDRIVE`); `env://PATH`.

## Examples

### Bad (Triggers V042)

```python
result = run_reveal('env://HOME')
```

### Good (Passes V042)

```python
monkeypatch.setenv('REVEAL_TEST_VAR', 'x')
result = run_reveal('env://REVEAL_TEST_VAR')    # or env://PATH
```

## Suppression

`# noqa: V042 <why>` on the literal's (first) line.

## Development

### Testing

```bash
pytest tests/test_posix_env_uri_rule_back1707.py -v
```

### Implementation Notes

- `find_posix_env_uris(tree)` is the importable scan. A test module that cannot be read or
  parsed is reported as an unavailable prerequisite instead of being skipped silently.
- Samples in the rule's own test are built from a concatenated `env:` + `//`, so no
  literal in that file reads as an input URI (the old scan excluded its own file by path).
- Findings use posix display paths relative to the checkout root.
