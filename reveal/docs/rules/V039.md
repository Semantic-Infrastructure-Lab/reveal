# V039: POSIX path literal in a test that breaks on Windows

## Overview

Dogfooding rule that checks reveal's own `tests/` for three line patterns that hold
on Linux and macOS and fail on Windows, where `str(path)` uses backslashes. It is
`scripts/check_windows_compat.py` (BACK-1470) moved into `reveal reveal:// --check`
(BACK-1707): same regexes, same exempt files, same findings, one report with the other
V-rules. The script and its CI/ci-local steps are gone. The rule also checks
native Path expectations about envelope sources and stderr (BACK-2590).

Only fires via `reveal reveal:// --check` (self-check of the dev checkout); it
does not run against user code.

## Rule Details

- **Code**: V039
- **Category**: validation
- **Severity**: MEDIUM
- **File Patterns**: `reveal://` self-check only (`internal = True`)

Scans `tests/**/test_*.py` (not `conftest.py`) and flags:

- `path-assign`: `m.path = Path('/fake/x.py')` -- a POSIX absolute Path assigned to a
  mock's `.path` (roots `/fake`, `/tmp`, `/home`, `/var`, `/src`, `/usr`);
- `posix-literal`: an `assert`/`assertEqual`/`assertIn` line holding a quoted
  `/fake/...`-style filesystem path (two or more segments, same roots);
- `path-split-on-slash`: `r['file'].rsplit('/', 1)` on a `file*`/`path*`/`dir*` value.
- Native Path output assertions: positive `str(path) in result.stderr`, or equality
  of a known builder's `source` field with `str(path)`, including `assertEqual`.
  Path bindings must be established locally through pathlib constructors or the
  standard temporary-path fixtures. The source builder must receive a Path:
  `ResultBuilder.create`, `ResultBuilder.create_error` or `add_cli_contract_fields`.
  Explicit string-source echoes stay valid. The rule applies the current envelope
  contract: Path sources emit POSIX spelling. These checks are strict, with no baseline.

The three legacy line patterns do not flag comment lines or lines using `native(`, `str(Path(`, `.as_posix()` or any
`://` URL, or Path-to-Path comparisons. All patterns exclude the POSIX-data test files (nginx, ssl, cpanel,
xlsx, letsencrypt, `test_uri.py`, ...; see `SAFE_FILES` in `V039.py`). The new check
does not treat negative leakage guards, native stdout or generic `path`/`file`
metadata as normalized envelope sources. It does not infer arbitrary helper or
fixture return types.

## Examples

### Bad (Triggers V039)

```python
assert result['file'] == '/fake/x.py'
```

### Good (Passes V039)

```python
assert result['file'] == native('/fake/x.py')   # native() from tests/conftest.py
```

Use `PureWindowsPath(x).name` / `os.path.basename(x)` instead of splitting on `'/'`.
For a builder given a Path, compare `source` with `path.as_posix()`. For an
OS-error stderr diagnostic, compare directory components and the filename:
`OSError` repr can double Windows backslashes. Do not replace an intentionally
native string-source echo with a normalized expectation.

## Suppression

`# noqa: win-path` (the spelling the repo already used) or `# noqa: V039` on the line.

## Development

### Testing

```bash
pytest tests/test_windows_path_rule_back1707.py tests/test_windows_lint_back2590.py -v
```

### Implementation Notes

- The legacy patterns remain line-based; `find_windows_path_hazards(lines)` is
  their importable scan. Native output assertions use the shared Python statement
  index and scoped local bindings, not a second whole-file AST traversal. A test file that cannot be read or decoded is reported as an
  unavailable prerequisite instead of being skipped silently.
- Findings use posix display paths relative to the checkout root.
