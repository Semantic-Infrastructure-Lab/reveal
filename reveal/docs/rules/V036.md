# V036: Fork-dependent test (start-method portability)

## Overview

Dogfooding rule that checks reveal's own `tests/` for a test whose injection into
pool workers only reaches a **forked** worker. Python starts pool workers with
`spawn` on Windows and macOS and with `forkserver` on Linux from CPython 3.14;
those workers re-import the test's modules and never see a patch made in the test
process. The local gate (3.12 on Linux) forks, so such a test is green there and
red in CI. BACK-1681's dying-worker tests did exactly this (fixed by 991424a3).

Only fires via `reveal reveal:// --check` (self-check of the dev checkout); it
does not run against user code.

## Rule Details

- **Code**: V036
- **Category**: validation
- **Severity**: MEDIUM
- **File Patterns**: `reveal://` self-check only (`internal = True`)

A module is flagged when it has all three:

1. an injection: `monkeypatch.setattr(...)`, `patch(...)`/`patch.object(...)`, or
   `os._exit(...)` (patching the pool constructor itself, a spy or a failing pool,
   does not count: the parent builds the pool);
2. a process pool in the test process: `ProcessPoolExecutor`/`Pool` named in code,
   `REVEAL_MAX_WORKERS` set above 1 or unset, or the `real_worker_pool` marker;
3. no start-method guard anywhere in the module.

## Examples

### ❌ Bad (Triggers V036)

```python
@pytest.fixture
def two_workers(monkeypatch):
    monkeypatch.setenv("REVEAL_MAX_WORKERS", "2")

# 'fork' is available on macOS and py3.14 Linux; it is just not the default
pytestmark = pytest.mark.skipif("fork" not in multiprocessing.get_all_start_methods(), reason="...")

def test_worker_dies(tmp_path, monkeypatch, two_workers):
    monkeypatch.setattr(file_checker, "check_and_collect_file", dies_on_one_file)
    ...
```

### ✅ Good (Passes V036)

```python
from conftest import needs_forked_workers  # skipif the default start method is not fork

@needs_forked_workers
def test_worker_dies(tmp_path, monkeypatch, two_workers):
    ...
```

Better still, run the pool in a subprocess forced to each start method, with an
injection every worker loads from disk (see
`tests/test_pool_start_methods_back1704.py`, which uses a user rule).

## Guards recognised

`needs_forked_workers` (tests/conftest.py), `get_start_method()`,
`set_start_method(...)`, `mp_context=`, `get_context('<method>')`.
`'fork' in get_all_start_methods()` is **not** a guard.

### Implementation Notes

- Module-level heuristic (a fixture may patch what another test's pool runs);
  the reported line is an injection in a function that also runs a pool, else
  the module's first injection.
- AST-based, so code inside string literals (a subprocess driver's source) is
  not an injection. A cheap source pre-filter means only candidate modules are
  parsed.
- Suppress a reviewed site with `# noqa: V036 <why>` on the reported line.
