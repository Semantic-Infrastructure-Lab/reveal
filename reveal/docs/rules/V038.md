# V038: Raw subprocess bytes asserted on newlines without normalising

## Overview

Dogfooding rule that checks reveal's own `tests/` for assertions on a subprocess's
raw bytes that depend on how the platform ends a line. Windows text-mode stdout
writes every `\n` as `\r\n`, even when the input was LF, so
`assert b'\r' not in r.stdout` passes on Linux and macOS and fails on every
Windows CI job. BACK-1706's `tests/test_crlf_sources_back1706.py` did exactly this
(fixed by 79a576c9 with a helper that drops the platform's own pair first).

Only fires via `reveal reveal:// --check` (self-check of the dev checkout); it
does not run against user code.

## Rule Details

- **Code**: V038
- **Category**: validation
- **Severity**: MEDIUM
- **File Patterns**: `reveal://` self-check only (`internal = True`)

A module is flagged when it has all three:

1. a subprocess call in byte mode: `subprocess.run/check_output/Popen/call/check_call`
   with no `text=`, `universal_newlines=`, `encoding=` or `errors=` (and no `**kwargs`);
2. an assertion on captured bytes (a name assigned from such a call, or a
   `.stdout`/`.stderr`) against a bytes literal that depends on line endings:
   `b'\r' in/not in x`, `x == b'a\r\n'`, `x.count(b'\n')`, `x.split(b'\n')`,
   `x.startswith(b'a\n')`, `x.splitlines(keepends=True)`, ...;
3. no Windows guard and no `.replace(b'\r\n', ...)` anywhere in the module.

Not flagged because they hold on Windows too: `b'\n' in out`, `out.endswith(b'\n')`
and plain `out.splitlines()` (handles `\r\n`).

## Examples

### ❌ Bad (Triggers V038)

```python
r = subprocess.run([sys.executable, '-m', 'reveal', name], capture_output=True, timeout=120)
assert b'\r' not in r.stdout   # Windows: every \n arrives as \r\n
```

### ✅ Good (Passes V038)

```python
def _own_newlines(data):
    """Drop the platform's own terminator; a CR leaked from the source still shows."""
    return data.replace(b'\r\n', b'\n') if sys.platform == 'win32' else data

assert b'\r' not in _own_newlines(r.stdout)
```

Or run with `text=True, encoding='utf-8'`, or parse the output (JSON) and assert
on values.

## Guards recognised

Anywhere in the module: `sys.platform == 'win32'` (or `!=`, or
`sys.platform.startswith('win')`), `os.name == 'nt'`, `platform.system() == 'Windows'`,
`.replace(b'\r\n', ...)`.

### Implementation Notes

- Heuristic and module-level: a guard or a normalising replace anywhere exempts
  the module. The captured bytes are tracked only as names assigned (in the same
  function) from a subprocess call or `.stdout`/`.stderr`; bytes that came from a
  helper in another module are not followed. String (decoded) comparisons on
  `\r` are not flagged.
- A cheap source pre-filter (a subprocess mention and a bytes literal with a
  `\r`/`\n` escape) means only candidate modules are parsed.
- Suppress a reviewed site with `# noqa: V038 <why>` on the reported line.
